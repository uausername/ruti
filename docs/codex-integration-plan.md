# План использования ruti из Codex

Дата исследования: 2026-10-27. Статус: интеграция CLI реализована и проверена; см. ниже.

## Реализовано

- `RUTI_HOST=codex`, `RUTI_SESSION_ID` и fallback на `CODEX_THREAD_ID`; Codex ID
  изолированы префиксом `codex:`. Старый Claude ID сохраняется без изменений.
- Ledger хранит host и не использует Claude quota session для Codex.
- В режиме Codex quota неизвестна, Claude candidates исключены, текущий исполнитель
  называется `codex:self`. Неизвестная квота не повышает давление при ранжировании Codex.
- `ruti install --host codex` показывает отдельную установку инструкций в
  `~/.codex/AGENTS.md`; `--apply` сохраняет прежний файл и пользовательский текст.
  Настройки Claude и OpenCode при этом не меняются.
- Снимки содержимого файлов учитывают повторные изменения уже dirty-файлов.
- `--local-only` направляет модельные запросы напрямую на LM Studio через отдельный
  provider OpenCode; удалённые providers отключены, основной и вспомогательный
  model совпадают. При неудаче загрузки brief не передаётся исполнителю.
- Логи, task files, running markers и usage разделены по run ID. Proxy callback
  получает ID через HTTP header. Прокси перезапущен и реальная корреляция проверена.
- `ruti report --host codex` отделяет историю Codex, учитывает verdict и показывает
  принятые/отклонённые результаты. В Codex lines offloaded считаются только для
  принятых запусков. Расход подписки и его экономия остаются unknown.
- `ruti delegate --worktree` создаёт отдельный detached checkout от HEAD, сохраняет
  patch и оставляет исходные staged/unstaged/untracked правки на месте. Перенос
  выполняет отдельная команда `ruti worktree apply --run ID --dir ORIGINAL_PROJECT`
  с проверкой hash patch, source HEAD и конфликтов, без изменения source index.
  Worktree сохраняется, в том числе после таймаута; автоматического удаления нет.

Проверена доступность Python 3.12.3, OpenCode 1.18.13 и работающего прокси.
В первой проверке LM Studio был недоступен. Сквозной `ruti delegate` через Gemini успешно
создал `smoke.txt` с проверенным содержимым `RUTI_CODEX_OK` в отдельном временном
Git-каталоге (run `245d6944`, 20,6 секунды). JSON назвал реальную модель
`gemini/gemini-2.5-flash` и изменённый файл; стоимость осталась неизвестной.
Предыдущий вывод о недоступности executable объясняется ограничениями sandbox.

Инструкции установлены в глобальный Codex AGENTS.md с резервной копией.
Полный набор до worktree: 844 passed, 1 failed. Сбой
`test_a_bash_redirect_into_a_nested_checkout_gets_its_letters` воспроизведён отдельно
на исходном HEAD во временной копии; он существовал до этой адаптации.

Сквозной параллельный тест: два отдельных временных Git-каталога, один Gemini alias,
оба файла проверены и приняты. Run IDs `4c457bece6db` и `2ccaba06024c`: четыре и три
запроса соответственно, 106,8 и 95,7 секунды. Цена провайдером не сообщена.
Это проверка корректности учёта, не репрезентативный benchmark производительности.

Local-only: LM Studio запущен, но первый запрос OpenCode 1.18.13 потребовал 17 447
токенов при загруженном контексте 16 384. После исправления оценки overhead до
18 000 + response headroom + brief, planner отказал до отправки задания: для
Qwen3-4B требовалось 5749 MiB при доступных 5048 MiB. Поэтому успешная локальная
генерация на текущем железе не подтверждена. Автоматический CPU offload не включался.

Local-only ограничивает маршрутизацию модели, а не сетевые действия tools/MCP.
Параллельные задачи должны работать в разных checkouts/worktrees: снимки файлов
не определяют автора одновременных правок одного checkout.

Остаются: выбор локальной модели/контекста под 6 GB VRAM,
репрезентативное измерение пользы на реальных задачах и опциональный MCP.

Worktree использует committed baseline: незакоммиченные изменения не копируются.
Поэтому этот режим следует выбирать для задач, которым достаточно HEAD.
Изоляция снижает риск случайного смешивания правок, но не заменяет sandbox ОС.
Git-тесты проверяют текстовые/бинарные patch, сохранение source index, конфликт
без частичного применения, подмену patch, изменение HEAD, неправильный checkout,
повторное применение, таймаут, коммиты исполнителя и подмену его Git pointer.
Реальный worktree smoke с Gemini пока не принят: первый запуск записал файл в
неправильный каталог (добавлен запрет external_directory и требование relative paths),
второй истёк по таймауту 120 секунд без результата. Source index и staged-правки
во втором запуске сохранились. Это ограничение live-проверки, а не успешный benchmark.
После добавления worktree полный прогон дал 858 passed и 2 failed: прежний сбой
timemachine и Windows-особенность теста записи скрытого файла `.git`. Последняя
исправлена открытием существующего файла вместо CREATE_ALWAYS; повторная проверка
исправленного теста и связанных сценариев: 22 passed. Заключительный прогон всех
worktree-сценариев после исправлений: 15 passed.

### Использование из PowerShell

```powershell
$env:RUTI_HOST = 'codex'
$env:RUTI_SESSION_ID = 'stable-id-for-this-conversation'
ruti status --json
ruti delegate --model gemini-flash --task-file task.md --dir C:\path\to\project --timeout 900 --json
# После проверки diff и тестов:
ruti verdict ok --run RUN_ID
ruti report --host codex --json
# Для локального маршрута без fallback:
ruti delegate --model local-qwen3-4b --local-only --task-file task.md --dir C:\path\to\project --json
```

Один session ID нужно сохранять во всех командах одной беседы. Для новых сессий
использовать новый ID; при доступном `CODEX_THREAD_ID` можно не задавать
`RUTI_SESSION_ID` вручную. Для проверки установки: `ruti install --host codex`.

## Вывод

Codex может использовать существующий ruti как внешний инструмент делегирования:
Codex готовит задачу → `ruti delegate` → OpenCode → LiteLLM → выбранный backend →
Codex проверяет diff и тесты. Переписывать прокси и исполнителя не требуется.
Для повседневного использования нужен небольшой адаптер сессий и установки.
Для корректной автоматической маршрутизации нужно отделить политику Claude от ядра.

Это делегирование отдельных задач. Оно не переключает backend текущей беседы Codex,
не переносит её контекст автоматически и не даёт основания обещать определённый
процент экономии подписки. Планирование, описание задачи и проверка остаются в Codex.

## Исходное состояние до реализации

| Компонент | Текущее состояние | Следствие для Codex |
| --- | --- | --- |
| `ruti/delegate.py`, `ruti/cli.py` | `delegate` принимает `--model`, `--task-file`, `--dir`, `--timeout`, `--json`; по умолчанию 900 секунд | Уже подходит для вызова из shell-инструмента Codex |
| Исполнитель | Запускается `opencode run --dir … --model … --auto …`; лог остаётся на диске | Codex может читать краткий результат, затем конкретный diff |
| Модели | В `opencode/opencode.json` есть `local-llama-31-8b`, `local-qwen3-4b`, `gemini-flash` и другие | Указанный в старых инструкциях `lm-studio-local` отсутствует в этом списке; alias нужно проверять по работающей конфигурации |
| `litellm/config.yaml` | Общий `default_fallbacks` удалён | Старое описание автоматического перехода local → Gemini уже не соответствует этому файлу |
| `ruti/sessions.py` | Источник session ID — только `CLAUDE_CODE_SESSION_ID` | Без адаптера режимы и выключение нельзя надёжно привязать к сессии Codex |
| `ruti/ledger.py` | При отсутствии session ID возможен fallback к `quota.json` | Запуск Codex может быть ошибочно отнесён к сессии Claude |
| `ruti/router.py` | Кандидаты `claude:self`, haiku/sonnet; ранжирование использует `quota.load()` | `ruti route` пока нельзя считать корректным советчиком для Codex |
| `ruti/install.py` | Устанавливает настройки, hooks и агентов в `~/.claude` | `ruti install --apply` не устанавливает интеграцию Codex |
| Состояние | По умолчанию `%LOCALAPPDATA%/ruti`; есть `RUTI_HOME` | Нужно учитывать доступ sandbox к логам, состоянию и инструментам |
| Учёт изменений | Сравниваются строки `git status --porcelain` до и после | Повторное изменение уже dirty-файла с тем же статусом может не попасть в отчёт |
| Подмена backend | Есть probe и анализ usage; обнаруженная подмена сама по себе не останавливает запуск | Для строгого local-only нужна политика, запрещающая удалённый маршрут, а не только уведомление |

В этой сессии `Get-Command ruti,opencode,python` не обнаружил доступные команды.
Пути Python/npm присутствуют в PATH, но это не подтверждает доступность исполняемых
файлов в текущем sandbox. Реальный вызов модели, доступность прокси и установленная
версия OpenCode не проверены. Это ограничение проверки, а не доказательство поломки
установки на машине пользователя.

До исследования рабочее дерево уже содержало изменение `opencode/opencode.json`.
Оно не менялось в рамках этого исследования.

## Этап 1. Проверить минимальный рабочий путь

1. В среде Codex определить доступные полные пути к Python 3.12, `ruti` и настоящему
   `opencode.exe`; проверить версии и поддержку аргументов текущего wrapper.
2. Проверить доступ к localhost:4000, реальный список aliases, LM Studio и путям
   состояния. Не запускать установку Claude и не менять глобальный PATH автоматически.
3. В отдельном тестовом каталоге выполнить одну маленькую задачу через существующий
   `ruti delegate`; сначала выбрать реально доступный local alias. При недоступности
   backend завершить проверку с понятной причиной, без серии повторных вызовов.
4. Проверить JSON, созданный файл, diff, exit code, журнал и реально ответившую модель.
5. Проверить таймаут: Codex должен получить управление, проверить оставшиеся файлы
   и принять решение; истечение времени не означает, что изменений нет.

Шаблон команды, после проверки доступности alias и исполняемых файлов:

```powershell
ruti delegate --model local-llama-31-8b --task-file .ruti/task.md --dir . --timeout 900 --json
```

Долгий процесс следует запускать с возвратом идентификатора фоновой shell-сессии и
проверять порциями. Задания передавать файлом, без shell-интерполяции текста.
Текущая реализация всё равно передаёт текст OpenCode через argv и ограничивает brief
24 000 символами; `--task-file` этого ограничения не снимает.

Критерий: воспроизводимый вызов из реальной сессии Codex с проверенным результатом.

## Этап 2. Минимальная постоянная интеграция

1. Добавить нейтральные `RUTI_HOST` и `RUTI_SESSION_ID`; сохранить совместимость с
   `CLAUDE_CODE_SESSION_ID`. Передавать непротиворечивый session ID на протяжении
   одной сессии Codex; фактический источник ID проверить в используемом клиенте.
2. Добавить host в ledger и изолировать quota/context/modes по host и session.
   Для Codex исключить fallback на Claude session из `quota.json`.
3. Подготовить инструкцию Codex: делегировать ограниченные задачи реализации,
   явно задавать каталог и допустимые файлы, получать JSON, проверять diff и тесты,
   фиксировать `ruti verdict … --run …`. Архитектуру и финальную проверку оставить Codex.
4. Добавить отдельную установку для Codex с preview и резервными копиями:
   например, `ruti install --host codex`. Существующий путь Claude сохранить.
   Начать с краткого AGENTS.md; повторяемую процедуру вынести в skill при необходимости.
5. Явно описать разрешения на проект, state/logs и сеть. Вызов внешнего исполнителя
   не должен использоваться для обхода ограничений или отказа в разрешении Codex.

Критерий: разные сессии Claude и Codex не смешивают режимы, статистику и выключение;
Codex применяет процедуру из разных проектов без ручного копирования длинного prompt.

## Этап 3. Корректная маршрутизация для Codex

1. Вынести сведения о ведущем агенте в host adapter: текущий исполнитель, доступные
   возможности, источник квоты, контекст и допустимые действия управления сессией.
2. Для Codex использовать нейтрального `self` и существующих local/remote исполнителей.
   Исключить советы запустить Claude subagent или переключить Claude seat.
3. При отсутствии подтверждённой телеметрии Codex хранить квоту как unknown.
   Не подставлять Claude budget и не преобразовывать unknown в якобы измеренный процент.
   Сначала использовать политику по размеру, сложности, риску, задержке и стоимости задачи.
4. Не переносить автоматически Claude hooks, statusline, wait/flow и команды смены
   model/effort. Добавлять аналоги только при подтверждённой поддержке целевого клиента.
5. Добавить тесты: host-specific candidates, unknown quota, изоляция сессий и регрессии Claude.

Критерий: `route` в режиме Codex выдаёт только выполнимые рекомендации и честно
обозначает неизвестную квоту.

## Этап 4. Надёжность делегирования

1. Исправить обнаружение изменений: учитывать содержимое до/после, tracked/untracked
   файлы, удаления и переименования. Покрыть изменение уже dirty-файла отдельным тестом.
2. Для задач с существенными правками использовать отдельный worktree, если проект
   поддерживает этот workflow. Переносить результат после проверки, сохраняя исходные
   незакоммиченные изменения. Доступные файлы и команды ограничивать средствами runner,
   поскольку текст brief сам по себе не является ограничением доступа.
3. Добавить строгую local-only/no-fallback политику на уровне маршрута прокси;
   отказ загрузки локальной модели должен останавливать задачу до передачи brief.
   Preflight probe сам по себе не гарантирует локальность всех последующих запросов.
4. Идентифицировать running marker, task/log filenames и usage по run ID.
   Сейчас running marker общий, а имена части файлов используют время с точностью до
   секунды; параллельные запуски требуют отдельной проверки и корреляции запросов.
5. Различать техническое завершение и принятый результат. Проверять scope, diff и
   релевантные тесты перед положительным verdict; exit 0 недостаточен.

Критерий: нет потери исходных правок, ложной атрибуции работы и удалённого выполнения
в local-only режиме; timeout и частичный результат воспроизводимо обрабатываются.

## Этап 5. Опциональный MCP и измерение пользы

MCP добавлять после рабочего CLI-пути, если это упростит использование в целевом
клиенте. Возможный интерфейс: status, route, delegate_start, delegate_poll,
delegate_result, verdict. Долгие запуски оформлять как jobs. Ограничить доступ
разрешёнными проектами; сохранить те же правила разрешений, что у CLI.

На нескольких сопоставимых задачах измерить время до принятого результата,
стоимость внешнего backend, объём возвращённого контекста, долю принятых запусков
и объём исправлений ведущим агентом. Экономию квоты Codex указывать только при наличии
подходящей телеметрии; proxy usage не измеряет расход подписки Codex.

Приоритет реализации: этап 1 → этап 2 → этап 3 и исправления этапа 4 → измерение.
MCP остаётся опциональным. Переписывание LiteLLM, LM Studio и OpenCode не требуется.
